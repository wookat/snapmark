## 发现清单

### R5-1【P2｜功能】1×1 等极小光栅图可进入编辑器但完全不可用：画布显示为一个像素点，工具无从操作
- 复现：上传 1×1 PNG → 编辑器打开，画布 1×1（shots/r5-1x1.png 中央仅一个点）。
- 对比：SVG 已有 <1024 上采样，光栅图没有。normalizeImage 只处理"过大"与"SVG 过小"，漏掉"光栅过小"。
- 建议：统一规则——最长边 <256 的光栅图同样按整数倍 nearest-neighbor 放大（保像素风格）并提示；或拒绝 <8px 图并 toast。思辨：截图工具的真实输入几乎不会是 1×1，但 16~64px 图标是常见输入，放大处理有真实价值。

### R5-2【P2｜功能】20000×10 极端长宽比图：等比缩放后显示高度仅 0.7px，画布不可见不可操作
- 复现：上传 20000×10 PNG → 编辑器内只有一条发丝线（shots/r5-wide.png）。面积 0.2MP 不触发 16MP 降采样，宽度适配后高度趋近 0。
- 建议：显示层给画布最小可视尺寸（如短边 <40px 时提供缩放/横向滚动查看），或在 normalizeImage 中对长宽比 >50:1 的图给出提示。思辨：长截图（网页全页 20000px 高）是真实场景——竖版等价问题同样存在，值得在显示层解决而非拒绝。

### R5-3【P2｜功能】Crop 拖选 <10px 静默忽略，无任何反馈
- 代码：`if (cw < 10 || ch < 10) return`（onPointerUp）。用户小幅误拖后以为裁剪失败/卡住。
- 建议：静默阈值内给 toast「Selection too small」或直接不设下限（等比放大后仍可用）。

### R5-4【P2｜逻辑】/api/track 的非 POST 方法返回 404 而非 405（Allow: POST）
- 复现：`curl -X PUT /api/track` → 404。REST 语义应 405；404 会误导集成方以为路径不存在。一行 `app.all` 兜底即可。属低成本正确性修缮。

### R5-5【P2｜文案/功能】动图 GIF 静默丢帧：上传动画 GIF 仅取首帧、导出为静态 PNG，全程无提示
- 复现：上传 anim.gif → 编辑正常但动画丢失，导出 PNG。用户若期待保留动画会困惑。
- 建议：检测 `type==='image/gif'` 时提示「GIF 将按首帧静态处理」。不建议支持动图编辑（范围失控，勿增实体）。
